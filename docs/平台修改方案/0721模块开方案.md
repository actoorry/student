# 仓库模块（wms）功能定位与需求清单

> 版本：v3.2 | 2026-08-02

---

## 核心表（6 张）

| 表 | 用途 |
|----|------|
| `wms_warehouse` | 位置树（虚拟 id1-6 + 实体仓库/库区/库位） |
| `wms_order_type` | 出入库单据行为配置 |
| `wms_stock` | 库存快照 |
| `wms_order` + `wms_order_item` | 出入库/调拨统一单据 |
| `wms_inventory_adjust` | 盘点记录 |
| `wms_stock_log` | 流水台账 |

---

## 一、位置模型

虚拟仓（id 1-6，tenant_id=1，parent_id=自身）系统预置。实体仓库（parent_id=0）用户自建。

```
id=1  供应商      parent_id=1
id=2  客户        parent_id=2
id=3  盘点差异    parent_id=3
id=4  报废        parent_id=4（三期）
id=5  生产        parent_id=5（预留）
id=6  在途        parent_id=6

id=100+  原料仓  parent_id=0    实体仓库
  ├── A区
  │   ├── A-01
  │   └── A-02
  └── B区
```

---

## 二、设计决策

| # | 决策 |
|---|------|
| 1 | 位置单表树形，parent_id=0 实体仓库，parent_id=自身 虚拟仓 |
| 2 | 批次号内联，由 product_spu.stock_mode 判断必填 |
| 3 | 出入库/调拨走 `wms_order`，盘点走 `wms_inventory_adjust` |
| 4 | 盘点一行一条、审核即时生效 |
| 5 | 入库类 stock_impact=1，负数=减库存 |
| 6 | `no` bigint Redis 自增，多租户 TenantBaseDO，不做锁库 |

---

## 三、库表设计

### 3.1 wms_warehouse

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键（1-6 保留给虚拟仓，用户数据从 100 起） |
| parent_id | bigint | ? | 上级节点。0=实体仓库根节点；等于自身 id=虚拟仓（不可移动） |
| name | varchar(100) | ? | 名称，如"原料仓"、"A区"、"A-01" |
| code | varchar(50) | | 编码，非必填，无唯一约束，仅用于展示或外部系统对接 |
| area_id | int | | 归属城市区县，关联 Area.getId()，用于按区域筛选仓库 |
| address | varchar(255) | | 详细地址，实体仓库层级填写 |
| partner_id | bigint | | 仓库负责人，FK → partner.id |
| status | tinyint | ? | 0=禁用（不可用于出入库） 1=启用 |
| sort | int | ? | 同级排序，越小越前 |
| remark | varchar(500) | | 备注 |

> **说明**：单表树形管理所有位置。虚拟仓（id 1-6，tenant_id=1）SQL 脚本一次性写入，用户不可见不可编辑。用户创建实体仓库时 parent_id=0，创建库区时 parent_id=仓库ID，创建库位时 parent_id=库区ID。删除校验：有子节点或有关联库存时拒绝删除。禁用后不可在新单据中选择。

---

### 3.2 wms_order_type

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| name | varchar(50) | ? | 单据类型名称，如"采购入库" |
| from_location_id | bigint | | 创建单据时默认带入的来源位置。0=用户自选实体位置，1-6=固定虚拟仓 |
| to_location_id | bigint | | 创建单据时默认带入的去向位置。0=用户自选，1-6=固定虚拟仓 |
| stock_impact | tinyint | ? | 库存影响方向：1=入库（增库存，减库存用负数 quantity） 2=出库（减库存） |
| need_supplier | tinyint | ? | 是否强制填写供应商：0=否 1=是（采购入库时必填 wms_order.supplier_id） |
| need_customer | tinyint | ? | 是否强制填写客户：0=否 1=是（销售出库时必填 wms_order.customer_id） |
| active | tinyint | ? | 是否启用。停用后创建单据时不可选 |
| sort | int | ? | 排序 |
| remark | varchar(500) | | 备注 |

**初始数据**：

| id | name | from | to | impact | supplier | customer |
|----|------|------|----|--------|---------|---------|
| 1 | 采购入库 | 1 | 0 | 1 | 1 | 0 |
| 2 | 其他入库 | 0 | 0 | 1 | 0 | 0 |
| 3 | 销售出库 | 0 | 2 | 2 | 0 | 1 |
| 4 | 其他出库 | 0 | 0 | 2 | 0 | 0 |
| 5 | 调拨出库 | 0 | 6 | 2 | 0 | 0 |
| 6 | 调拨入库 | 6 | 0 | 1 | 0 | 0 |

> **说明**：每种出入库业务对应一条类型配置。创建单据时根据 type 自动填充默认 from/to 位置、判断是否必填客商、确定审核后库存增减方向。from/to 中 `0` 表示用户手工选择实体仓库或库位。新增业务类型只需插入一条记录，无需改代码。

---

### 3.3 wms_stock

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| sku_id | bigint | ? | 产品 SKU ID，FK → product_sku.id |
| warehouse_id | bigint | ? | 所属实体仓库 ID，FK → wms_warehouse.id（parent_id=0） |
| location_id | bigint | ? | 存储库位 ID，FK → wms_warehouse.id（叶子节点） |
| stock_mode | tinyint | ? | 冗余自 product_spu.stock_mode，方便查询时无需 join。0=不管理 1=批次 2=序列号 |
| batch_no | varchar(50) | | 批次号。stock_mode=0 时为 NULL；stock_mode=1 时用户录入；stock_mode=2 时存序列号 |
| production_date | date | | 生产日期，批次管理时使用 |
| expiry_date | date | | 有效期至 |
| quantity | decimal(12,2) | ? | 库存数量（最小单位）。正数，允许 0（仅记录库位-产品关系） |
| unit_price | decimal(12,2) | | 最近入库单价（移动平均），仅入库类单据更新 |

> **说明**：**一张表管理所有库存**。`warehouse_id + location_id + sku_id + batch_no + production_date + expiry_date` 唯一确定一条库存记录。`stock_mode` 冗余自 product_spu，方便库存查询时无需 join 产品表即可判断批次管理方式。`quantity=0` 的记录保留，由定时任务清理。入库审核时 upsert（MERGE）：按唯一键匹配则累加数量、更新单价；无匹配则新增。出库审核时按 FIFO 扣减（expiry_date 近效期优先）。

| status | tinyint | ? | 0=草稿 1=待审核 2=已审核 3=已完成 -1=已取消 |
| supplier_id | bigint | | 供应商 ID，FK → partner.id。need_supplier=1 时必填 |
| customer_id | bigint | | 客户 ID，FK → partner.id。need_customer=1 时必填 |
| from_warehouse_id | bigint | ? | 来源位置。实体库位或虚拟仓 ID |
| to_warehouse_id | bigint | ? | 去	向位置。实体库位或虚拟仓 ID |
| origin_id | bigint | | 源单据 ID。如来自采购单或销售单 |

| remark | varchar(500) | | 备注 |

> **说明**：**所有影响 wms_stock 的单据统一用此表**，通过 type_id 区分采购入库/销售出库/调拨出库/调拨入库/其他出入库。from/to 值含义：0=用户自选实体位置，1-6=固定虚拟仓，其他=实体库位 ID。审核后写 wms_stock_log。

| 2 | 其他入库 | 用户选 | 用户选 | — | — |
| 3 | 销售出库 | 用户选实体仓 | 2（客户） | — | ? |
| 4 | 其他出库 | 用户选 | 用户选 | — | — |
| 5 | 调拨出库 | 用户选实体仓 | 6（在途） | — | — |
| 6 | 调拨入库 | 6（在途） | 用户选实体仓 | — | — |

### 3.5 wms_order_item

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| order_id | bigint | ? | 出入库单 ID，FK → wms_order.id |
| sku_id | bigint | ? | 产品 SKU ID，FK → product_sku.id |
| origin_id | bigint | | 来源明细 ID（如 purchase_order_item.id），用于回写已收数量 |
| from_location_id | bigint | ? | 来源位置。实体库位或虚拟仓 ID |
| to_location_id | bigint | ? | 去向位置。实体库位或虚拟仓 ID |
| batch_no | varchar(50) | | 批次号。stock_mode≠0 时必填，入库手动录入，出库按 FIFO 自动匹配 |
| production_date | date | | 生产日期 |
| expiry_date | date | | 有效期至 |
| quantity | decimal(12,2) | ? | 移动数量（绝对值）。入库=入库量，出库=出库量 |
| unit_price | decimal(12,2) | | 单价，仅入库时可选填写 |

> **说明**：每条明细 = 一次库存移动。审核时：stock_impact=1 按 to_location 增库存，stock_impact=2 按 from_location 减库存。虚拟仓（id 1-6）位置不参与库存变更，仅记录在流水表中。出库时系统按 FIFO（先进先出，按 expiry_date 近效期优先）自动匹配批次。

### 3.6 wms_inventory_adjust

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| no | bigint | ? | 单据编号，Redis INCR 生成 |
| warehouse_id | bigint | ? | 盘点仓库，FK → wms_warehouse.id（实体仓库） |
| sku_id | bigint | ? | 产品 SKU ID，FK → product_sku.id |
| location_id | bigint | ? | 库位 ID，FK → wms_warehouse.id |
| batch_no | varchar(50) | | 批次号 |
| production_date | date | | 生产日期 |
| expiry_date | date | | 有效期至 |
| book_quantity | decimal(12,2) | ? | 账面数量，系统从 wms_stock 读取的当前库存 |
| actual_quantity | decimal(12,2) | ? | 实盘数量，用户实际盘点后填入 |
| status | tinyint | ? | 0=草稿 1=已审核（审核后自动更新 wms_stock） |
| check_type | tinyint | ? | 1=全盘 2=抽盘 3=手动调整 |
| check_time | datetime | | 盘点时间 |
| operator_id | bigint | | 操作人 ID |
| remark | varchar(500) | | 备注 |

> **说明**：一行一条，不建明细表。用户打开库存列表 → 在某一行上直接修改实盘数 → 保存为草稿 → 审核。审核时计算 `diff = actual - book`，diff>0 盘盈（from=3 盘点差异 → to=库位，stock +diff），diff<0 盘亏（from=3 盘点差异 → to=库位，stock -diff），diff=0 跳过。手动调整（check_type=3）同理。审核后写 wms_stock_log(biz_type=''adjust'')。不生成中间调整单。

---

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| sku_id | bigint | ? | 产品 SKU ID |
| warehouse_id | bigint | ? | 实体仓库 ID |
| from_location_id | bigint | ? | 来源位置（虚拟仓或实体库位） |
| to_location_id | bigint | ? | 去向位置（虚拟仓或实体库位） |
| batch_no | varchar(50) | | 批次号 |
| production_date | date | | 生产日期 |
| expiry_date | date | | 有效期至 |
| biz_type | varchar(20) | ? | 来源业务：order=出入库单 / adjust=盘点调整单 |
| biz_id | bigint | ? | 业务单据 ID（wms_order.id 或 wms_inventory_adjust.id） |
| biz_no | bigint | ? | 业务单据编号，冗余方便查询 |
| before_quantity | decimal(12,2) | ? | 本次变动前的库存量 |
| change_quantity | decimal(12,2) | ? | 本次变动量。入库为正、出库为负 |
| after_quantity | decimal(12,2) | ? | 本次变动后的库存量 |

> **说明**：只追加不修改（无 updater/update_time/deleted 字段）。每次 wms_order 审核或 wms_inventory_adjust 审核时，为每个发生库存变更的 item 写入一条流水。记录 from→to 两个位置以及变动前后的库存快照。用于库存追溯、对账、审计。

## 四、product 新增

| 表 | 字段 | 类型 | 说明 |
|----|------|------|------|
| product_spu | stock_mode | tinyint | 库存管控方式：0=不管理（默认） 1=批次管理 2=序列号管理 |
| product_sku | safety_stock_min | decimal(12,2) | 安全库存下限，低于此值触发预警 |
| product_sku | safety_stock_max | decimal(12,2) | 最大库存上限，高于此值触发预警 |

> **说明**：`stock_mode` 决定 wms 模块中批次号是否必填、库存如何汇总。safety_stock_min/max 用于库存预警看板，应用层对比 wms_stock.quantity 判断。

## 五、盘点流程

```
库存列表页 → 用户在某行直接改"实盘数" → 保存：生成 wms_inventory_adjust(status=0)
  → 审核(status 0→1)：
      diff = actual - book
      diff > 0：from=3 to=库位 qty=+diff → stock 增加
      diff < 0：from=3 to=库位 qty=-diff  → stock 减少（入库类负数）
      diff = 0：跳过
  → 写 wms_stock_log(biz_type=''adjust'')
```

---

## 六、出入库审核逻辑

```
遍历 wms_order_item：
  stock_impact=1：to 实体库位加库存，quantity 负则减
  stock_impact=2：from 实体库位减库存
  虚拟仓位置不参与 wms_stock 变更
  每行 item 写一条 wms_stock_log(biz_type=''order'')
```


# 采购管理模块（purchase）功能定位与需求清单

> 版本：v1.0 | 2026-08-02 | 参考：Odoo purchase 模块

---

## 核心表（2 张 + 1 张在 product）

| 表 | 用途 |
|----|------|
| `purchase_order` | 采购单头 |
| `purchase_order_item` | 采购明细 |
| `product_rel_supplier` | 供应商-产品关系（价格/交期/起订量，属于 product 模块） |

---

## 一、模块定位

purchase 是 **采购业务的中枢**，负责从下单 → 审核 → 到货入库（对接 wms）的全流程。

### 与其它模块的关系

```
partner（客商）           product（产品中心）
     │                        │
     │ supplier_id            │ sku_id / spu_id
     ▼                        ▼
  ┌─────────────────────────────────────┐
  │         purchase（采购管理）          │
  │  采购单 → 审核 → 生成 wms 入库待办    │
  └──────────────────┬──────────────────┘
                     │ 审核后触发
                     ▼
  ┌─────────────────────────────────────┐
  │         wms（仓库管理）               │
  │  wms_order(type=采购入库) → 收货     │
  │  收货完成 → 回写 purchase_order_item │
  └─────────────────────────────────────┘
```

### 与 Odoo 的核心差异

| 项目 | Odoo purchase | 本方案 |
|------|--------------|--------|
| 状态机 | draft→sent→purchase→done→cancel | 草稿→待审核→已审核→部分入库→已入库→已取消 |
| 询价(RFQ) | 独立 draft/sent 状态 | 草稿下标记"询价中"，不做独立状态 |
| 发票匹配 | purchase.bill.line.match | 一期不涉及（accountant 模块后续对接） |
| 框架协议 | Blanket Order | 二期 |
| 自动补货 | 与 stock 紧密集成 | 一期手动创建，二期对接补货建议 |

---

## 二、设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | 头行分离 | `purchase_order` 存供应商/状态/金额；`purchase_order_item` 存明细 |
| 2 | `no` bigint Redis 自增 | 与 wms 一致 |
| 3 | 多租户 TenantBaseDO | 与 wms 一致 |
| 4 | 状态驱动、审核后自动生成 wms 入库单 | 审核通过 → 自动创建 wms_order(type=采购入库, status=草稿) |
| 5 | 供应商价格独立管理 | `product_rel_supplier`（product 模块）维护报价/起订量/交期/供应商编码 |
| 6 | 暂不考虑财务 | accountant 模块目前仅支付功能，采购发票匹配二期对接 |
| 7 | 单价不含税 | unit_price = 不含税单价，税额 application 层按税率计算 |
| 8 | wms 收货回写 | wms 入库审核时回写 purchase_order_item.received_quantity，收齐自动完成 |

---

## 三、库表设计

### 3.1 purchase_order

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| no | bigint | ? | 采购单号，Redis INCR 生成 |
| supplier_id | bigint | ? | 供应商 ID，FK → partner.id |
| status | tinyint | ? | 0=草稿 1=待审核 2=已审核 3=部分入库 4=已入库 -1=已取消 |
| order_date | datetime | ? | 下单日期，默认当前时间 |
| expected_delivery_date | datetime | | 预计到货日期 |
| origin_id | bigint | | 源单据 ID（如来自补货建议） |
| total_amount | decimal(12,2) | | 不含税金额合计 |
| tax_amount | decimal(12,2) | | 税额合计（application 层计算） |
| discount_amount | decimal(12,2) | | 整单折扣金额 |
| operator_id | bigint | | 制单人/采购员 ID |
| remark | varchar(500) | | 备注 |

> **说明**：状态流转 `草稿(0)` → 提交 `待审核(1)` → 审核 `已审核(2)`。审核时自动生成 wms_order(type=采购入库)。wms 收货后回写 item.received_quantity，全部收齐自动变为 `已入库(4)`。草稿可取消(-1)，已审核不可取消。

### 3.2 purchase_order_item

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| order_id | bigint | ? | 采购单 ID，FK → purchase_order.id |
| sku_id | bigint | ? | SKU ID，FK → product_sku.id |
| spu_id | bigint | | 冗余 SPU ID，FK → product_spu.id |
| quantity | decimal(12,2) | ? | 采购数量（最小单位） |
| unit_id | bigint | ? | 采购单位，FK → product_unit.id |
| unit_price | decimal(12,2) | ? | 不含税单价（优先取 product_rel_supplier.price） |
| discount | decimal(5,2) | | 折扣百分比 |
| tax_rate | decimal(5,2) | | 税率百分比，默认取系统配置 |
| amount | decimal(12,2) | ? | 行金额 = quantity × unit_price × (1 - discount/100) |
| received_quantity | decimal(12,2) | ? | 已入库数量，wms 收货回写累加，默认 0 |
| expected_delivery_date | datetime | | 预计到货日期，从 product_rel_supplier.delivery_lead_time 推算 |
| supplier_product_code | varchar(100) | | 供应商产品编码，下单时带入 |

## 五、业务流程

### 5.1 采购下单完整流程

```
1. 创建采购单（草稿 status=0）
   → 选择供应商 → 自动带出 buyer_id
   → 添加明细：选 SKU → 自动匹配 product_rel_supplier 价格/交期
   → 保存

2. 提交审核（0→1）

3. 审核通过（1→2）
   → 自动生成 wms_order：
       type=采购入库, from=1(供应商虚拟仓), to=收货仓库
       origin_id = purchase_order.id
       wms_order_item.origin_id = purchase_order_item.id

4. wms 收货入库
   → 仓库操作员填写实收数、批次号
   → 审核 wms_order → 库存增加
   → 回写 purchase_order_item.received_quantity

5. 入库完成
   → 全部收齐 → order.status 2→4（已入库）
   → 部分收货 → order.status 2→3（部分入库）
```

### 5.2 状态流转图

```
草稿(0) ──提交──▶ 待审核(1) ──审核通过──▶ 已审核(2)
  │                                        │
  │                                        ├── 部分入库 ──▶ 部分入库(3)
  │                                        │                  │
  │                                        │                  └── 全部入库 ──▶ 已入库(4)
  └──────── 取消 ──────────────────────────────────────────────────▶ 已取消(-1)
```

# 生产模块（mes）功能定位与需求清单

> 版本：v1.0 | 2026-08-02 | 二期 | 参考：Odoo MRP 模块

---

## 核心表（4 张）

| 表 | 用途 |
|----|------|
| `mes_bom` | BOM 头（成品 + 标准用量） |
| `mes_bom_item` | BOM 明细（原料清单） |
| `mes_order` | 生产订单 |
| `mes_workcenter` | 工作中心（产线/工位） |

---

## 一、模块定位

mes 是 **生产过程管理**，负责从 BOM 定义 → 生产订单 → 原料投料（对接 wms 出库）→ 成品入库（对接 wms 入库）的闭环。

### 与其它模块的关系

```
product（产品中心）
     │
     │ BOM 定义：成品 + 原料配比
     ▼
  ┌─────────────────────────────────────┐
  │           mes（生产管理）             │
  │  BOM → 生产订单 → 投料/入库          │
  └──────┬──────────────────┬───────────┘
         │                  │
         │ 原料出库          │ 成品入库
         ▼                  ▼
  ┌─────────────────────────────────────┐
  │           wms（仓库管理）             │
  │  生产领料出库 / 生产入库             │
  └─────────────────────────────────────┘
         │                  │
         │ 扣减原料库存      │ 增加成品库存
         ▼                  ▼
  ┌─────────────────────────────────────┐
  │           wms_stock                  │
  └─────────────────────────────────────┘
```

### 与 Odoo MRP 的核心差异

| 项目 | Odoo MRP | 本方案（二期） |
|------|----------|--------------|
| 订单状态 | draft→confirmed→progress→done→cancel | 草稿→待审核→已审核→生产中→已完成→已取消 |
| 工序/工步 | mrp.routing.workcenter + mrp.workorder | 一期不做工序级管理，仅 BOM + 订单 |
| 工作中心 | mrp.workcenter（资源日历、OEE） | 简化为档案表，记录名称和费率 |
| 拆解单 | mrp.unbuild | 二期不做 |
| 副产品 | mrp.bom.byproduct | 二期不做 |
| 替代物料 | BOM line 支持替代 | 一期不做 |
| 物料消耗弹性 | flexible/warning/strict | 一期不做弹性控制，严格按 BOM 扣料 |
| 与 wms 交互 | stock.move 多层调度 | 直接生成 wms_order（生产领料 + 生产入库） |

---

## 二、设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | BOM 头行分离 | `mes_bom` 存成品信息，`mes_bom_item` 存原料配比 |
| 2 | 一期不做工序管理 | 订单直接关联 BOM，不设 routing/workorder，降低复杂度 |
| 3 | 订单审核后自动生成 wms 单据 | 生产领料出库（原料） + 生产入库（成品），两单同时生成 |
| 4 | 严格按 BOM 投料 | 不设消耗弹性，领料数量 = BOM 用量 × 生产数量 |
| 5 | `no` bigint Redis 自增 + 多租户 TenantBaseDO | 与 wms/purchase 一致 |
| 6 | 工作中心简化 | 仅做档案管理，不涉及排程、资源日历、OEE |
| 7 | 成本核算一期不做 | 生产成本归集（人工/制造费用）待三期 |

### 3.1 mes_bom

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| no | varchar(50) | | BOM 编号，手动录入 |
| name | varchar(100) | ? | BOM 名称，如"番茄酱-标准配方" |
| spu_id | bigint | ? | 成品 SPU ID，FK → product_spu.id |
| sku_id | bigint | | 成品 SKU ID（多规格区分），FK → product_sku.id |
| quantity | decimal(12,2) | ? | 标准生产数量（成品）。如 100kg/批 |
| unit_id | bigint | ? | 成品单位，FK → product_unit.id |
| workcenter_id | bigint | | 默认工作中心，FK → mes_workcenter.id |
| routing_template_id | bigint | | 工艺路线模板，FK → mes_routing_template.id |
| cycle_time | decimal(10,4) | | 每件标准耗时（秒）。整条生产线的节拍，如 0.5 秒/件。初始为人工预估，后续根据实际订单自动修正 |
| status | tinyint | ? | 0=禁用 1=启用 |
| is_default | tinyint | ? | 是否默认 BOM。同一成品只有一个默认，创建订单时自动带出 |
| version | int | ? | 版本号，BOM 变更时递增 |

> **说明**：一个成品可有多个 BOM（不同版本/不同产线），`is_default=1` 的在创建订单时自动带出。BOM 变更后 `version` 递增，历史订单不受影响。同一 `spu_id + sku_id + version` 唯一。
>
> **产能说明**：`cycle_time` 是整条生产线的节拍（一件产品从头到尾的总耗时），初始为人工预估，后续根据实际订单自动修正。产能（件/小时）= 3600 / cycle_time，运行时计算不存储。

### 3.2 mes_bom_item

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ? | 主键 |
| bom_id | bigint | ? | BOM ID，FK → mes_bom.id |
| sku_id | bigint | ? | 原料 SKU ID，FK → product_sku.id |
| quantity | decimal(12,2) | ? | 标准用量（原料），基于 BOM 的成品标准生产数量 |

| scrap_rate | decimal(5,2) | | 损耗率(%)，如 2.00 = 2%。实际投料量 = quantity × (1 + scrap_rate/100) |
| sort | int | ? | 行排序 |
| remark | varchar(500) | | 备注 |

> **说明**：每条 item = 生产 1 个标准批量的成品所需的 1 种原料。`scrap_rate` 用于计算额外投料（如 2% 损耗 → 领料 102）。订单按实际生产数量等比缩放：实际用量 = quantity × (订单数量 / BOM 成品数量)。

| unit_id | bigint | ? | 成品单位，FK → product_unit.id |
| workcenter_id | bigint | | 工作中心，FK → mes_workcenter.id |
| status | tinyint | ? | 0=草稿 1=待审核 2=已审核 3=生产中 4=已完成 -1=已取消 |

| planned_finish_date | datetime | | 计划完成时间 |
| actual_start_date | datetime | | 实际开始时间 |

## 五、业务流程

### 5.1 生产订单完整流程

```
1. 维护 BOM
   → 选择成品 SPU/SKU，设置标准产量
   → 添加原料明细：选 SKU、标准用量、损耗率
   → 关联默认工作中心
   → 启用（status=1）

2. 创建生产订单（草稿 status=0）
   → 选择 BOM（自动带出成品、工作中心）
   → 填写计划生产数量、计划时间
   → 系统等比计算各原料需求用量

3. 提交审核（0→1）

4. 审核通过（1→2）
   → 自动生成 2 张 wms_order（status=草稿）：
       a. 生产领料出库：type=7, from=实体仓, to=5(生产)
          item.quantity = BOM用量 × (订单数量 / BOM成品数量) × (1 + scrap_rate/100)
       b. 生产入库：type=8, from=5(生产), to=成品仓
          item.quantity = 订单成品数量

5. 生产领料（wms 审核出库单）
   → 原料从仓库发往生产线 → 扣减 wms_stock（原料）
   → 订单状态 2→3（生产中）

6. 生产入库（wms 审核入库单）
   → 成品从生产线入仓 → 增加 wms_stock（成品）
   → 订单状态 3→4（已完成）
```

### 5.2 状态流转图

```
草稿(0) ──提交──▶ 待审核(1) ──审核通过──▶ 已审核(2)
  │                                        │
  │                                        ├── 领料完成 ──▶ 生产中(3)
  │                                        │                  │
  │                                        │                  └── 入库完成 ──▶ 已完成(4)
  └──────── 取消 ──────────────────────────────────────────────────▶ 已取消(-1)
```

### 5.3 原料用量计算示例

```
BOM 定义：成品"番茄酱"，标准产量 100kg
  ├── 原料A：番茄，用量 120kg，损耗率 2%
  └── 原料B：白糖，用量 10kg，损耗率 1%

订单：生产 200kg 番茄酱（BOM 标准产量的 2 倍）

计算：
  原料A 投料 = 120 × 2 × (1 + 2%) = 244.8 kg
  原料B 投料 = 10 × 2 × (1 + 1%) = 20.2 kg
```

## 七、工序/工步管理（routing / workorder）

> 参考 Odoo MRP 的 `mrp.routing.workcenter`（工序定义）+ `mrp.workorder`（工单执行）
> 本方案整合为「工艺路线模板 + BOM 工艺路线 + 工序工单」三层模型。

### 7.1 与 Odoo 的对应关系

| Odoo MRP | 本方案 | 说明 |
|----------|--------|------|
| `mrp.routing.workcenter`（直接挂 BOM） | `mes_routing_template` + `mes_routing_template_operation` | 拆为模板表 + 模板工序表，可复用 |
| — | `mes_routing_operation` | BOM 实际工艺路线（从模板复制而来） |
| `mrp.workorder` | `mes_workorder` | 工序工单（生产订单审核后自动生成） |
| `mrp.workcenter` | `mes_workcenter`（已有） | 工作中心，复用二期表 |
| `mrp.workcenter.productivity` | 不做 | 工时记录三期再做 |
| `blocked_by_operation_ids` | `prev_operation_id` | 工序前后依赖，简化为单向前驱 |

### 7.2 核心设计

```
工艺路线模板（mes_routing_template）  ← 可复用，一次定义多次引用
  └── 模板工序（mes_routing_template_operation，1:N）
        ├── 工序1：备料 → 工作中心A → 30min
        ├── 工序2：加工 → 工作中心B → 120min
        └── 工序3：质检 → 工作中心C → 15min

BOM（mes_bom）
  └── 关联模板（routing_template_id）
        → 保存时从模板复制工序到 mes_routing_operation（快照）

生产订单（mes_order）审核通过
  └── 自动生成工序工单（mes_workorder，1:N）
        ├── WO-001：备料 → 待开始
        ├── WO-002：加工 → 待开始（依赖 WO-001 完成）
        └── WO-003：质检 → 待开始（依赖 WO-002 完成）
```

> **为什么需要模板？** 同类产品工艺相同（如所有酱类都是"备料→杀菌→灌装→质检"），模板定义一次，BOM 引用即可，避免每个 BOM 重复维护工序。

### 7.3 新增表：mes_routing_template（工艺路线模板）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ✓ | 主键 |
| no | varchar(50) | | 模板编号 |
| name | varchar(100) | ✓ | 模板名称，如"酱类标准工艺""包装类通用工艺" |
| description | varchar(500) | | 适用范围说明 |
| status | tinyint | ✓ | 0=禁用 1=启用 |
| remark | varchar(500) | | 备注 |

**模板修改规则：**
- 模板被 BOM 引用后（存在 `mes_bom.routing_template_id = 本模板ID`），**不可修改**工序
- 如需修改，**复制当前模板生成新模板**，在新模板上改，然后切换 BOM 引用
- 模板可**禁用**（status=0），禁用后新 BOM 不可引用，已有引用不受影响

### 7.4 新增表：mes_routing_template_operation（模板工序）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ✓ | 主键 |
| template_id | bigint | ✓ | 所属模板，FK → mes_routing_template.id |
| name | varchar(100) | ✓ | 工序名称，如"备料""杀菌""灌装""质检" |
| workcenter_id | bigint | ✓ | 工作中心，FK → mes_workcenter.id |
| sequence | int | ✓ | 工序顺序（10/20/30...） |
| prev_operation_id | bigint | | 前置工序 ID（null=首道工序） |
| time_cycle | decimal(10,2) | | 标准工时（分钟/件） |
| time_setup | decimal(10,2) | | 准备时间（分钟） |
| description | varchar(500) | | 工序说明/作业指导 |

> **引用模式**：BOM 只存 `routing_template_id`，运行时（生成工单时）直接查 `mes_routing_template_operation` 获取工序。不再有 `mes_routing_operation` 表，模板修改后所有引用该模板的 BOM 自动生效。

### 7.5 mes_bom 扩展字段

在已有 `mes_bom` 表新增：

| 字段 | 类型 | 说明 |
|------|------|------|
| routing_template_id | bigint | 关联工艺路线模板，FK → mes_routing_template.id |

### 7.6 新增表：mes_workorder（工序工单）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | ✓ | 主键 |
| no | varchar(50) | | 工单编号 |
| order_id | bigint | ✓ | 生产订单，FK → mes_order.id |
| template_id | bigint | ✓ | 工艺模板，FK → mes_routing_template.id |
| template_operation_id | bigint | ✓ | 模板工序，FK → mes_routing_template_operation.id |
| workcenter_id | bigint | ✓ | 工作中心，FK → mes_workcenter.id |
| sequence | int | ✓ | 执行顺序 |
| status | tinyint | ✓ | 0=待开始 1=进行中 2=已完成 3=已跳过 -1=已取消 |
| qty_planned | decimal(12,2) | ✓ | 计划数量（=订单生产数量） |
| qty_done | decimal(12,2) | | 实际完成数量 |
| date_planned_start | datetime | | 计划开始时间（排程生成） |
| date_planned_end | datetime | | 计划结束时间（排程生成） |
| date_actual_start | datetime | | 实际开始时间 |
| date_actual_end | datetime | | 实际完成时间 |
| duration_expected | decimal(10,2) | | 预计工时（分钟） |
| duration_actual | decimal(10,2) | | 实际工时（分钟） |
| operator | varchar(50) | | 操作人 |
| remark | varchar(500) | | 备注 |

### 7.7 工序工单状态流转

```
待开始(0) ──开始──▶ 进行中(1) ──完成──▶ 已完成(2)
    │                  │
    │                  └── 取消 ──▶ 已取消(-1)
    └── 跳过 ──▶ 已跳过(3)
```

**工序依赖规则：**
- 工单按 `sequence` 排序执行
- 前一道工序 `status=2`（已完成）或 `3`（已跳过）后，下一道工序才可开始
- 最后一道工序完成时，触发生产订单状态 `3→4`（生产中→已完成）

### 7.8 工单自动生成逻辑

```
生产订单审核通过（status 1→2）
    ↓
检查 BOM 是否关联工艺模板（routing_template_id）
    ├── 有 → 检查模板状态
    │       ├── 模板启用（status=1）→ 按模板工序顺序生成 mes_workorder（status=0 待开始）
    │       │     首道工单可立即开始，其余等待前序完成
    │       └── 模板已禁用（status=0）→ 抛异常："工艺模板已禁用，请重新绑定 BOM 的工艺路线模板"
    └── 无 → 跳过工序管理，直接走原流程（领料→入库）
```

> **兼容性**：BOM 没关联模板的，走原流程不变。关联了模板的，审核时自动生成工序工单。模板被禁用的，审核报错，需重新绑定。

### 7.9 模板管理规则汇总

| 操作 | 允许 | 拦截条件 |
|------|------|---------|
| 新建模板 | ✅ | — |
| 修改模板工序 | ✅ | 无 BOM 引用时可改 |
| 修改模板工序 | ❌ | 有 BOM 引用时拦截，提示"模板已被 N 个 BOM 引用，请复制为新模板后修改" |
| 复制模板 | ✅ | 永远允许，生成新模板（名称后缀"_副本"），可自由修改 |
| 禁用模板 | ✅ | 已引用的 BOM 不受影响（已有引用不变），但新 BOM 不可引用禁用模板 |
| 删除模板 | ❌ | 有 BOM 引用时不可删除，需先解绑所有 BOM |

## 八、生产排程

> 二期只做**订单级排程**（BOM 产能），不做工序级排程。
> 工序工单只做执行跟踪（待开始/进行中/已完成），计划时间字段留空，三期再填。

### 8.1 排程设计

```
输入：
  - 生产订单的计划开始时间
  - BOM 的 cycle_time（每件标准耗时，秒）

计算：
  订单总时长 = cycle_time × 生产数量
  计划开始 = order.date_planned_start
  计划结束 = 计划开始 + 订单总时长

输出：
  mes_order 的 date_planned_start / date_planned_end
```

### 8.2 排程示例

```
BOM：番茄酱，cycle_time = 0.5 秒/件
产能 = 3600 / 0.5 = 7200 件/小时

生产订单：1000 件，计划开始 10:00

订单排程：
  总时长 = 0.5 × 1000 = 500 秒 ≈ 8.3 分钟
  计划开始 = 10:00:00
  计划结束 = 10:08:20
```

### 8.3 排程触发时机

| 时机 | 动作 |
|------|------|
| 生产订单审核通过 | 自动排程（订单级） |
| 手动点击「重新排程」 | 按当前时间重新计算 |
| 实际完成时间偏离计划 | 不自动重排，仅标红预警 |

### 8.4 实际产能自动修正

每次生产订单完成（status 3→4）后，系统自动记录并修正 BOM 的 `cycle_time`：

```
实际 cycle_time = 实际耗时 / 成品数量

实际耗时 = 订单 date_actual_end - date_actual_start

修正规则：
  取最近 N 笔订单的实际 cycle_time 加权平均
  更新 BOM 的 cycle_time 字段
```

**示例：**
```
BOM 初始 cycle_time = 5 秒/件（人工预估）

第1次生产 1000 件，实际耗时 1.5 小时 → 实际 5.4 秒/件
第2次生产 2000 件，实际耗时 2.8 小时 → 实际 5.04 秒/件
第3次生产 500 件，实际耗时 0.7 小时 → 实际 5.04 秒/件

average(5.4, 5.04, 5.04) = 5.16 秒/件
→ 更新 cycle_time = 5.16
```

### 8.5 工序工单不做排程

| 工序工单字段 | 二期 | 三期 |
|-------------|------|------|
| status（执行状态） | ✅ 做待开始/进行中/已完成 | — |
| operator（操作人） | ✅ 记录 | — |
| date_actual_start / date_actual_end | ✅ 记录实际时间 | — |
| date_planned_start / date_planned_end | ❌ 留空 | ✅ 排程填入 |
| duration_expected | ❌ 留空 | ✅ 排程计算 |
| duration_actual | ✅ 记录实际工时 | — |

### 8.6 排程不做的事

| 不做 | 原因 |
|------|------|
| 工序级排程 | 二期不做，三期根据实际工时数据再排 |
| 资源日历 | 不考虑工作中心休息日/节假日 |
| 甘特图拖拽 | 仅自动正向排程，不支持手动拖拽 |
| 产能约束拒绝 | 超产能仅预警不拦截 |
