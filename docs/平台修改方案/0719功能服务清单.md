# 原始需求描述
为了方便 开发人员或者AI工具 快速定位系统功能和业务功能，特此开发功能清单的服务类，BaseService是系统基础功能服务清单，其他模块单独建自己{模块}Service功能清单。

- 请将目前系统中 suxin-module 业务模块中的 system partner product 等三块业务功能，移动到 suxin-module-infra 模块中，与infra文件夹平级
- 然后，请将 suxin-module-infra 模块，改名为 suxin-module-base 系统模块。
- 以后 suxin-module-base 模块，将作为系统基础模块，负责系统层对业务层提供的功能服务模块
- 后续项目完成，将 suxin-framework 模块下的，各模块都将打包，不在对外提供源码。
- 目前系统已有功能服务清单类：src/main/java/vip/appap/suxin/module/system/util/BaseService.java 但功能比较少。请添加以下方面的调用：
  - partner方面的快速调用
  - product方面的快速调用
  - redis方面的快速调用
  - role权限方面的快速调用
  - dict数据字典的快速调用
  - file附件方面的快速调用
  - tenant租户方面的快速调用
- BaseService是给业务模块继承使用，各Service直接继承就可以调用，但系统模块不要继承。
- 其他业务模块也形成功能服务清单，方便调用，但不是为了继承使用，java不支持多继承。都放在util目录里

# 功能服务清单开发方案

## 一、目标

为开发人员和 AI 工具提供**统一的功能调用入口**，快速定位和调用系统基础能力。

- `BaseService` — 系统基础功能服务清单，业务模块 Service 继承使用
- `{模块}Service` — 各业务模块自己的功能清单，放 `util` 目录供调用

## 二、模块调整

### 2.1 目录迁移

```
当前：
suxin-module/src/main/java/vip/appap/suxin/module/
├── system/        ← 移到 infra
├── partner/       ← 移到 infra
├── product/       ← 移到 infra
├── mes/           ← 留在业务模块
├── sales/         ← 留在业务模块
└── ...

迁移后：
suxin-framework/suxin-module-infra/src/main/java/vip/appap/suxin/module/
├── infra/         ← 原有基础设施
├── system/        ← 移入
├── partner/       ← 移入
└── product/       ← 移入
```

### 2.2 模块改名

`suxin-module-infra` → `suxin-module-base`（系统基础模块）

涉及：
- 目录改名
- pom.xml 中 `<artifactId>`
- 所有 `import vip.appap.suxin.module.infra.*` → `import vip.appap.suxin.module.infra.*`

## 三、BaseService 功能扩充

### 3.1 当前已有能力

| 分类 | 方法 |
|------|------|
| 单号生成 | `getOrderNo()`、`getNo(prefix)` |
| 当前用户 | `getLoginUserId()`、`getLoginUser()` |
| 当前租户 | `getTenantId()`、`getRequiredTenantId()` |
| 对象转换 | `convert(source, clazz)` |

### 3.2 需要新增的能力

> **性能说明：** 所有依赖注入使用 `@Lazy` 延迟加载。业务模块继承 BaseService 后，只有真正调用对应方法时才初始化该依赖，不用的依赖不消耗启动时间和内存，请求调用性能不受影响。

#### A. partner 快速调用

```java
// ==================== partner 快速调用 ====================
@Resource
@Lazy  // 延迟注入，用到才初始化
protected PartnerService partnerService;

/** 获取合作伙伴（客户/供应商） */
protected PartnerDO getPartner(Long id) {
    return partnerService.getPartner(id);
}

/** 获取合作伙伴 Map */
protected Map<Long, PartnerDO> getPartnerMap(Collection<Long> ids) {
    return partnerService.getPartnerMap(ids);
}

/** 获取当前用户对应的 partner */
protected PartnerDO getCurrentPartner() {
    return partnerService.getPartner(getLoginUserId());
}
```

#### B. product 快速调用

```java
// ==================== product 快速调用 ====================
@Resource
@Lazy
protected ProductSpuService productSpuService;
@Resource
@Lazy
protected ProductSkuService productSkuService;

/** 获取产品 SPU */
protected ProductSpuDO getSpu(Long id) {
    return productSpuService.getSpu(id);
}

/** 获取产品 SKU */
protected ProductSkuDO getSku(Long id) {
    return productSkuService.getSku(id);
}

/** 获取 SKU 列表（按 SPU） */
protected List<ProductSkuDO> getSkuList(Long spuId) {
    return productSkuService.getSkuListBySpuId(spuId);
}
```

#### C. redis 快速调用

```java
// ==================== redis 快速调用 ====================
@Resource
@Lazy  // 不用的 Service 不建立 redis 连接池
protected StringRedisTemplate stringRedisTemplate;

/** 设置缓存 */
protected void setCache(String key, String value, Duration timeout) {
    stringRedisTemplate.opsForValue().set(key, value, timeout);
}

/** 获取缓存 */
protected String getCache(String key) {
    return stringRedisTemplate.opsForValue().get(key);
}

/** 删除缓存 */
protected void deleteCache(String key) {
    stringRedisTemplate.delete(key);
}
```

#### D. role 权限快速调用

## 四、BaseService 与业务模块的关系

### 4.1 继承规则

```
┌─────────────────────────────────┐
│       BaseService（基类）         │
│   ├─ partner/product 快速调用     │
│   ├─ redis/权限/字典/文件/租户     │
│   └─ 单号/用户/转换               │
└──────────────┬──────────────────┘
               │ extends（继承）
    ┌──────────┼──────────────┐
    ▼          ▼              ▼
SalesService  MesService     CrmService
(业务Service)  (业务Service)  (业务Service)
```

- **业务模块 Service**：继承 `BaseService`，直接获得所有基础能力
- **system 模块**：**不继承** BaseService（系统模块是基础能力的提供者，不消费）

### 4.2 其他业务模块的功能清单

Java 不支持多继承，所以其他业务模块的功能清单**不继承 BaseService**，而是放在 `util` 目录下，作为静态工具类或独立 Service 供调用：

```
vip.appap.suxin.module.{模块名}.util/
├── PartnerUtil.java      # 业务模块内 partner 功能清单
├── ProductUtil.java      # 业务模块内 product 功能清单
└── ...
```

> 各业务模块在 `util` 目录下建自己的功能清单，方便开发人员和 AI 工具快速找到该模块能调用的功能。
