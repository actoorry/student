# dating 后端包结构、菜单、权限编码清单

## 1. 文档目的

本文档定义 `dating` 域在当前项目中的第一版：

- 后端包结构
- Controller 路径规划
- 菜单规划
- 权限编码规范
- 页面组件命名建议

目标是让后续研发可以直接按本文档创建目录、类、菜单 SQL 和前端页面骨架。

## 2. 命名与落地原则

遵循当前项目规范：

- 所有业务代码继续放在 `suxin-module-system`
- 模块前缀统一使用 `dating`
- 权限编码采用 `模块名:表名:动作`
- Controller 路径采用 `/dating/{entity}`
- 管理后台 Controller 放 `controller.admin`
- App 接口放 `controller.app`

命名示例：

- `dating:profile:create`
- `dating:profile:update`
- `dating:profile:query`
- `dating:realname-verify:approve`

## 5. 菜单设计原则

结合当前项目 `member_menu.sql` 风格，建议婚恋中心菜单采用“每个页面独立顶级叶子菜单”的方式，减少目录层级复杂度。

建议菜单分三组：

- 平台运营菜单
- 商家/红娘菜单
- C 端不走 `system_menu`

## 8. 菜单 SQL 生成建议

建议仿照现有 `member_menu.sql` 风格：

- 每个功能页面一条 `type = 1` 的菜单记录
- 该菜单下挂 `type = 2` 的按钮权限
- `permission` 字段同时作为页面可见权限

示例风格：

```sql
INSERT INTO system_menu(name, permission, type, sort, parent_id, path, icon, component, component_name, status)
SELECT '实名认证', 'dating:realname-verify:query', 1, 200, 0, 'dating', 'ep:checked', 'dating/realname-verify/index', 'DatingRealnameVerify', 0
FROM DUAL WHERE NOT EXISTS (SELECT 1 FROM system_menu WHERE component = 'dating/realname-verify/index');
```

按钮示例：

```sql
INSERT INTO system_menu(name, permission, type, sort, parent_id, path, icon, component, component_name, status)
SELECT '实名认证通过', 'dating:realname-verify:approve', 2, 1, @menu_id, '', '', '', '', 0
FROM DUAL WHERE NOT EXISTS (SELECT 1 FROM system_menu WHERE permission = 'dating:realname-verify:approve');
```
