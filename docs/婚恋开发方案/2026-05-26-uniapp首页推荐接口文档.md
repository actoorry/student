# uniapp 首页推荐接口文档

## 1. 目标

本文档用于支撑 `UI/uniapp-marriage/pages/index/index.uvue` 首页“推荐”页面的数据对接，供后端直接按接口开发。

当前前端首页依赖的数据来源于：

- `UI/uniapp-marriage/pages/index/index.uvue`
- `UI/uniapp-marriage/data/mock-data.uts`

首页当前包含 3 类能力：

1. 获取推荐会员列表
2. 对推荐会员发送“满意”
3. 对推荐会员发送“Hi 打招呼”

## 2. 前端当前真实字段

首页当前页面实际使用字段如下：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | Long | 是 | 推荐会员 ID |
| name | String | 是 | 昵称/展示名 |
| age | Integer | 是 | 年龄 |
| city | String | 是 | 所在城市 |
| education | String | 是 | 学历 |
| job | String | 否 | 职业 |
| height | Integer | 是 | 身高，单位 cm |
| income | String | 否 | 收入文案，如 `8k-12k` |
| verifiedLabel | String | 是 | 认证标签，如 `已实名` |
| mainImage | String | 是 | 主图 |
| avatarImage | String | 否 | 头像 |
| onlineLabel | String | 否 | 在线状态文案，如 `在线`、`15分钟前活跃` |
| viewerLabel | String | 否 | 曝光/热度文案，如 `3人心动` |
| bio | String | 是 | 个人介绍 |
| tags | String[] | 是 | 顶部标签，前端当前取前 3 个展示 |
| interestTags | String[] | 是 | 详细标签；前端当前前 4 个偏基础资料，后续项偏择偶条件 |
| albumImages | String[] | 是 | 相册图片列表，建议 4 张及以上 |

## 3. 前端页面渲染规则

后端返回时需要注意这些前端约定：

1. `age` 前端最终展示为数字，建议后端直接传整数，前端自行拼接“岁”。
2. `height` 建议传整数，前端自行拼接 `cm`。
3. `verifiedLabel` 当前直接展示文案，不做状态换算。
4. `tags` 最少返回 3 个，否则顶部标签区域会显得空。
5. `interestTags` 建议最少返回 6 个：
   - 前 4 个用于“基础资料”区域
   - 第 5 个开始用于“择偶条件”区域
6. `albumImages` 建议最少返回 4 张。
7. 图片字段需返回可直接访问的完整 URL，或返回前端当前可识别的静态资源路径。

## 4. 推荐列表接口

### 4.1 接口信息

- 请求方式：`GET`
- 接口路径：`/app/marriage/recommend-member/page`

### 4.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNo | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 10；首页建议先给 10-20 |
| refreshType | Integer | 否 | 刷新类型：`1-首次加载` `2-下一个推荐池` `3-重新刷新` |
| city | String | 否 | 城市筛选 |
| minAge | Integer | 否 | 最小年龄 |
| maxAge | Integer | 否 | 最大年龄 |
| minHeight | Integer | 否 | 最小身高 |
| maxHeight | Integer | 否 | 最大身高 |
| education | String | 否 | 学历筛选 |
| datingGoal | String | 否 | 择偶目标筛选 |

说明：

- 当前首页代码还没有显式筛选 UI，但后端接口建议预留这些参数，后续加筛选不用改协议。
- 当前前端是本地数组左右滑切，后续接接口时可先一次性拉一批数据放本地切换。

## 5. “满意”接口

### 5.1 接口信息

- 请求方式：`POST`
- 接口路径：`/app/marriage/recommend-member/like`

### 5.2 请求参数

```json
{
  "targetUserId": 1001,
  "source": 1
}
```

### 5.3 参数说明

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| targetUserId | Long | 是 | 被操作的推荐会员用户 ID |
| source | Integer | 是 | 来源，建议固定：`1-首页推荐` |

### 5.4 响应体

```json
{
  "code": 0,
  "data": {
    "liked": true,
    "match": false,
    "toast": "已发送满意提醒，对方会立即收到通知"
  }
}
```

### 5.5 业务说明

1. 用户点击首页“满意”按钮时调用。
2. 后端需记录喜欢关系。
3. 若对方已喜欢当前用户，`match=true`，表示互相喜欢，可触发建联能力。
4. 后端建议同时触发站内信、订阅消息或 IM 通知。

## 6. “Hi 打招呼”接口

### 6.1 接口信息

- 请求方式：`POST`
- 接口路径：`/app/marriage/recommend-member/say-hi`

### 6.2 请求参数

```json
{
  "targetUserId": 1001,
  "content": "Hi，你好呀",
  "source": 1
}
```

### 6.3 参数说明

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| targetUserId | Long | 是 | 被打招呼用户 ID |
| content | String | 否 | 打招呼文案；为空则后端用默认文案 |
| source | Integer | 是 | 来源，建议固定：`1-首页推荐` |

### 6.4 响应体

```json
{
  "code": 0,
  "data": {
    "sent": true,
    "toast": "已发送Hi打招呼"
  }
}
```

### 6.5 业务说明

1. 如果平台有“聊天券”或会员限制，这里由后端统一校验。
2. 如果打招呼本质就是创建一条系统消息/会话首条消息，也可以在这里直接建会话。
3. 若余额不足、无聊天券、未实名，不要返回 500，直接返回明确业务错误码。

## 7. 推荐接口的访问前置条件

根据产品方案，首页推荐建议增加这些前置校验：

1. 当前用户已登录
2. 当前用户已完成实名认证
3. 当前用户资料完整度达到最低阈值时，推荐效果更好
4. 被推荐用户必须是：
   - 已上架/可推荐状态
   - 已实名认证
   - 未被当前用户拉黑
   - 非当前用户本人

## 8. 推荐排序建议

后端可先按简单版本实现，后续再升级算法：

1. 同城优先
2. 已实名认证优先
3. 活跃用户优先
4. 与当前用户择偶条件匹配度高者优先
5. 适当加入去重与曝光控制，避免重复刷到同一批人

## 9. 建议的业务错误码

| 错误码 | 说明 |
| --- | --- |
| `MARRIAGE_RECOMMEND_NOT_REAL_AUTH` | 未实名认证，不能查看推荐 |
| `MARRIAGE_RECOMMEND_EMPTY` | 当前暂无可推荐用户 |
| `MARRIAGE_RECOMMEND_MEMBER_NOT_EXISTS` | 推荐对象不存在 |
| `MARRIAGE_RECOMMEND_ALREADY_LIKED` | 已对该用户点过满意 |
| `MARRIAGE_RECOMMEND_HI_LIMIT` | 今日打招呼次数已达上限 |
| `MARRIAGE_RECOMMEND_HI_NEED_CHAT_TICKET` | 需要聊天券或会员权益 |
| `MARRIAGE_RECOMMEND_FORBIDDEN` | 当前无权操作该推荐对象 |

## 10. 后端最小落地范围

如果你要先快速开发一个可联调版本，最小只需要做这 3 个接口：

1. `GET /app/marriage/recommend-member/page`
2. `POST /app/marriage/recommend-member/like`
3. `POST /app/marriage/recommend-member/say-hi`

其中第一期可以先不做复杂算法，按基础条件分页返回即可。

## 11. 与当前前端的对接说明

前端后续改造建议如下：

1. 页面加载时调用推荐列表接口，填充本地 `recommendMembers`
2. 左右滑动仍然在本地数组中切换
3. 当前数组快到底时，再请求下一页/下一批数据
4. 点击“满意”调用 `like` 接口
5. 点击“Hi”调用 `say-hi` 接口

这样改动最小，能最快完成联调。
