# 首页与个人主页分享/互动按钮统一设计

- 日期：2026-06-26
- 主题：婚恋端首页推荐页与个人主页详情页分享按钮迁移、三枚悬浮操作统一、详情页头部主视觉向首页推荐卡对齐

## 1. 背景与目标

当前婚恋端存在两处交互与视觉不一致：

1. 首页推荐页的分享入口位于头部右上角，和底部 `Hi / 喜欢` 悬浮操作分离。
2. 个人主页详情页虽然已有 `分享 / Hi / 喜欢` 三枚操作，但分享按钮的视觉结构与另外两枚按钮不完全一致，且详情页头部主视觉与首页推荐卡不是同一套语言。

本次目标是：

- 将首页推荐页右上角分享按钮迁移到底部悬浮操作组。
- 首页与个人主页详情页统一为 `分享 / Hi / 喜欢` 三枚圆形悬浮按钮。
- 个人主页详情页头部主视觉尽量向首页推荐卡靠齐，形成“首页推荐卡的无滑动版”。
- 保持现有分享业务能力、关注能力、打招呼能力不变，不扩大到全站按钮系统重构。

## 2. 范围

### 2.1 本次纳入范围

- `UI/uniapp-marriage/pages/index/index.uvue`
- `UI/uniapp-marriage/pages/member-detail/index.uvue`
- 与上述两个页面直接相关的少量分享样式/逻辑收口（仅在确有必要时）

### 2.2 本次不纳入范围

- 不为详情页引入左右切换资料能力
- 不抽离完整公共推荐卡组件
- 不重做分享文案、分享参数、分享路径策略
- 不扩展到婚恋端其他页面的按钮视觉巡检

## 3. 用户确认结论

本次设计基于以下已确认结论：

1. 调整范围为“首页推荐页 + 个人主页详情页一起统一”。
2. 两个页面都统一为三枚并排操作：`分享 / Hi / 喜欢`。
3. 个人主页详情页向首页推荐页资料卡靠齐，可直接复用其视觉结构。
4. 详情页只复用视觉，不响应滑动；不接入上一位/下一位切换。

## 4. 方案对比与选型

### 方案 A（采用）：首页卡片视觉下沉到详情页，按钮组三枚完全统一

- 首页分享入口从头部迁移到底部悬浮组。
- 详情页头部结构尽量向首页推荐卡贴齐。
- 两个页面都使用 `分享 / Hi / 喜欢` 三枚圆形悬浮操作。

优点：

- 最贴近“完全同风格”的目标。
- 用户感知最强，一眼就能看出是同一套交互语言。
- 不改变业务链路，只改视觉和入口位置，风险可控。

代价：

- 详情页模板和样式调整较多。

### 方案 B：只统一按钮组，不完整复用首页卡片

优点是改动更小；缺点是详情页与首页仍会保留明显差异，不满足本次“靠齐复用”的目标。

### 方案 C：抽公共卡片组件做完全复用

优点是长期结构更干净；缺点是超出这轮“先完成视觉统一”的目标，改动和验证成本更高。

### 结论

采用方案 A：优先实现可见一致性，后续如有需要再考虑组件级收敛。

## 5. 页面设计

### 5.1 首页推荐页

现状：

- 头部大图右上角存在文字型分享按钮。
- 底部右侧仅有 `Hi` 与 `喜欢` 两枚悬浮操作。

调整后：

1. 删除头部右上角独立分享按钮展示。
2. 底部右侧悬浮操作组改为三枚并排统一风格按钮：
   - 分享
   - Hi
   - 喜欢
3. 分享按钮纳入与 `Hi / 喜欢` 相同的显隐逻辑与布局体系。
4. 首页卡片主体资料内容、滑动切换逻辑、分享回调逻辑保持不变。

### 5.2 个人主页详情页

现状：

- 已有 `分享 / Hi / 喜欢` 三枚悬浮操作，但视觉不完全统一。
- 顶部主视觉与首页推荐卡的层级和结构不同。

调整后：

1. 详情页头部主视觉尽量向首页推荐卡对齐，包括：
   - 大图背景区
   - 图片蒙层
   - 底部身份信息区
   - 顶部辅助信息胶囊区
2. 保留详情页自己的数据来源与页面结构，不引入推荐列表切换。
3. 三枚悬浮操作统一为与首页相同的圆形视觉和定位方式。
4. 图片预览、登录拦截、实名认证拦截、分享回调逻辑保持不变。

## 6. 视觉统一标准

### 6.1 按钮形态

三枚按钮统一为同尺寸正圆，保持相同：

- 宽高
- 圆角（50%）
- 阴影
- 背景层次
- 图标字号
- 图标在圆心中的视觉重心
- 按压反馈

允许 `分享 / Hi / 喜欢` 在颜色或图标字符上有区分，但不能改变其形体与层级。

### 6.2 布局与对齐

- 三枚按钮作为一个悬浮操作组处理。
- 首页与详情页使用一致的：
  - 右侧偏移
  - 底部安全区留白
  - 组内间距
  - 垂直排列节奏
- 分享按钮不能因为 `button` 默认样式导致位置偏移、尺寸不一或视觉发虚。

### 6.3 动效标准

- 显示/隐藏：统一使用现有 action bar 的透明度 + 位移过渡语言。
- 按下反馈：统一轻微缩放或阴影变化，不出现分享按钮独有的系统默认态。
- 不新增夸张跳动、单独延迟、特殊强调动画。

### 6.4 详情页头部统一标准

详情页头部需要尽量向首页推荐卡靠齐，重点统一：

- 图片蒙层浓度与氛围
- 底部身份信息卡的摆放方式
- 头像 / 姓名 / 年龄 / 认证标签的排列节奏
- 顶部辅助说明胶囊区的风格

详情页不需要复刻首页的滑动预览层、进度提示或切换手势相关表现。

## 7. 实现策略

### 7.1 首页推荐页实现策略

在 `UI/uniapp-marriage/pages/index/index.uvue` 中：

1. 移除顶部 `stage-action-group` 中的分享按钮展示。
2. 在底部悬浮操作区新增分享按钮，并接入与现有 `floating-action` 相同的样式体系。
3. 让分享按钮与现有 `actionBarVisible` 控制逻辑保持一致。
4. 保留现有 `open-type="share"` 能力，不改动分享回调定义。

### 7.2 个人主页详情页实现策略

在 `UI/uniapp-marriage/pages/member-detail/index.uvue` 中：

1. 参考首页推荐卡重构详情页顶部视觉结构。
2. 在不改变详情页业务逻辑的前提下，重排顶部模板层次。
3. 将现有分享按钮样式收敛到与 `Hi / 喜欢` 同一组圆形视觉。
4. 保留原有 `showInteractionButtons` 判定逻辑。

### 7.3 复用原则

本次优先“直接对齐和复用已有结构/样式语义”，而不是强行抽公共组件。

原因：

- 用户明确优先级是尽快统一首页和详情页视觉。
- 这轮不需要进行额外架构重构。
- 页面间先收敛命名、结构和样式后，再决定是否值得进一步组件化。

## 8. 风险与处理

### 风险 1：分享按钮使用 button 后出现默认样式差异

处理：

- 明确覆盖默认 button 样式。
- 以现有圆形悬浮按钮为基准校准尺寸、背景、边框、内边距和对齐。

### 风险 2：详情页头部照搬首页后引入不必要的推荐页语义

处理：

- 仅复用视觉层次，不带入推荐索引、滑动提示、预览影子卡等推荐页专属元素。

### 风险 3：改动模板较多导致局部遮挡或安全区错位

处理：

- 保持底部按钮定位策略一致。
- 完成后对首页、详情页分别检查底部安全区、右侧边距、滚动时显隐是否稳定。

## 9. 验收标准

完成后应满足：

1. 首页右上角不再出现独立分享按钮。
2. 首页底部右侧为 `分享 / Hi / 喜欢` 三枚同风格圆形按钮。
3. 详情页底部也是同样三枚按钮，视觉完全一致。
4. 详情页头部主视觉看起来是“首页推荐卡的无滑动版”。
5. 两个页面按钮的尺寸、阴影、间距、显隐动效一致。
6. 分享、打招呼、关注能力仍可正常触发。

## 10. 测试与验证

本次以页面行为与视觉一致性验证为主：

1. 首页检查：
   - 顶部分享入口已移除
   - 底部三枚按钮位置、间距、显隐一致
   - 点击分享仍能触发分享能力
2. 详情页检查：
   - 顶部主视觉已向首页推荐卡靠齐
   - 三枚按钮样式一致
   - 点击分享、Hi、喜欢分别仍走原有逻辑
3. 联合检查：
   - 两个页面同类按钮尺寸、阴影、位置一致
   - 无明显默认 button 样式残留

## 11. 后续计划边界

本设计只覆盖视觉统一和入口迁移。若本轮落地后效果稳定，再评估：

- 是否抽离公共资料卡组件
- 是否扩展到其他婚恋端页面的互动按钮统一
- 是否进一步统一分享 icon 与文案表现
